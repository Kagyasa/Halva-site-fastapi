# Обновление существующей установки

Изменения подготовлены относительно `f805e27392adaef23284aaa413406a06b059bbe3`.
Патч содержит исходный код, тесты, миграцию и инструкции; ваша база и `.env` в него не входят.

## Применить патч

Остановите сервер и обработчик писем. Сделайте резервную копию PostgreSQL средствами
pgAdmin или `pg_dump` и убедитесь, что копия действительно создана. Сохраните копию
своего `.env`; его нужно использовать дальше, добавляя недостающие настройки.

В чистой рабочей копии репозитория, из корня проекта:

```powershell
git status
git switch -c fix/reliability-and-cleanup
git apply --check "C:\Downloads\halva-fixes.patch"
git apply "C:\Downloads\halva-fixes.patch"
```

Замените путь на фактический путь скачанного файла. Если `git apply --check`
сообщает конфликт, сначала сравните ваши локальные изменения с патчем. Не запускайте
принудительное применение и не сбрасывайте свою работу.

Архив `halva-fixed.zip` — альтернативная полная копия исходников. Распакуйте его
в отдельную папку, перенесите туда собственный `.env`, создайте новое виртуальное окружение.
В архиве нет пользовательской базы, паролей и окружения Python.

## Обновить настройки и базу

Активируйте окружение Python и установите зависимости:

```powershell
python -m pip install -r requirements.txt
python -m app.cli generate-secret
```

Используйте сгенерированный ключ для `ADMIN_SECRET_KEY`, если прежний ключ был
заглушкой или отсутствовал. При смене ключа потребуется повторный вход в админку.
Локально оставьте `APP_ENV=development`, `ADMIN_SESSION_HTTPS_ONLY=false`;
`ALLOWED_HOSTS` должен содержать адрес, по которому открываете сайт.
SMTP, TLS и очередь описаны в README; без включённого обработчика письма остаются в базе.

```powershell
python -m alembic upgrade head
python -m alembic check
```

Миграция проверяет старые данные перед изменением схемы. Если она остановилась
из-за дублей, отрицательных цен или неверных диапазонов, исправьте именно указанные
записи и повторите команду. Чтобы открыть старую админку до миграции, используйте
отдельную копию прежней версии кода с прежней схемой. Не запускайте новый сервер
на базе, в которой новая миграция ещё не применена.

Пользователи и заявки сохраняются. Повторное создание администратора не требуется.
Существующие TG и MAX остаются прежними; команды заполнения больше не заменяют их.

## Проверить запуск

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Откройте сайт и админку, проверьте цены, точки, часы и телефоны из своей базы.
У сотрудника должны быть все незавершённые и неотменённые заявки; у администратора —
все статусы за последние два календарных месяца по дате создания.

Пока итоговых юридических документов нет, отправка заявок отключена.
Для включения загрузите готовые тексты командой `publish-legal` из README.
Заглушки и синтетические документы из тестов для этого не подходят.

## Проверки перед публикацией

Локально выполнены 29 серверных тестов на временной SQLite, проверки поведения
формы и витрины в DOM, Ruff и форматирование JavaScript. PostgreSQL и Chromium
предусмотрены в `.github/workflows/checks.yml`, но их результат пока не подтверждён:
интеграция GitHub вернула 403 при попытке записи, поэтому ветка и pull request
на GitHub не были созданы. Перед размещением нужно выполнить эти проверки
и осмотреть страницы в браузере на компьютере, планшете и телефоне.

Для отправки подготовленной ветки после применения и проверки патча:

```powershell
git add .
git commit -m "Fix order reliability, admin access and site data"
git push -u origin fix/reliability-and-cleanup
```

Откройте pull request в `main` и дождитесь завершения обоих заданий Checks.
Прямое слияние без этой проверки не требуется. Размещение на Timeweb описано
в [отдельной инструкции](deployment-timeweb.md).
